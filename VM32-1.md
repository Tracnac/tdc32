# VM32.01 Virtual Computer Specification

VM32.01 is the current browser-hosted virtual-computer platform for the TDC32.01 CPU. It defines the address map, system page, RAM/ROM, boot procedure, I/O board, video device, and host keyboard integration. CPU instruction encodings and behavior are specified in [TDC32-1.md](TDC32-1.md); source and assembler conventions are in [TOOLS32-1.md](TOOLS32-1.md).

## Memory map

| Address range | Use |
| --- | --- |
| `$0000–$00FF` | 64-entry system vector table; 64 big-endian words. |
| `$0100–$0113` | Stack-bank, boot, and memory registers. |
| `$0114–$01FF` | Shared system RAM. |
| `$0200–$02FF` | Memory-mapped I/O board registers. |
| `$0300–$03FF` | Reserved system-page aperture; accesses fault. |
| `$0400–$7FFF` | Installed RAM for programs, data, and stack storage. |
| `$8000–$FFFF` | 32 KiB ROM; instruction fetch is allowed, ordinary data access is not. |
| `$00010000–$000195FF` | 640×480, 1-bit-per-pixel framebuffer, MSB first. |

The system page is not ordinary RAM. The assembler/loader may not emit code or data bytes into `$0000–$03FF`. System RAM at `$0114–$01FF` is shared. Unassigned system-page and I/O-board locations fault. All multi-byte values are big-endian.

## Stack banks and system registers

R14 is banked by CUSR.S. The supervisor stack occupies `$0400–$3FFF`, with initial top `$4000`; the user stack occupies `$4000–$7FFF`, with initial top `$8000`. Stack pointers must be word-aligned and stay within the active bank. The system page is not stack storage.

| Address | Register | Access / meaning |
| --- | --- | --- |
| `$0100` | `SSP` | Current/saved supervisor stack pointer. Supervisor read/write; bank bounds are checked. |
| `$0104` | `USP` | Current/saved user stack pointer. Supervisor read/write; bank bounds are checked. |
| `$0108` | `BOOT_ENTRY` | Read-only entry address supplied by the loader. |
| `$010C` | `RAM_START` | Read-only `$00000400`. |
| `$0110` | `RAM_END` | Read-only exclusive end `$00008000`. |

The system-page vector table is readable by either mode and writable only in supervisor mode, except reset vector 0, which is read-only. The stack-bank registers at `$0100` and `$0104` are supervisor-only. The remaining system RAM is available to both modes.

## I/O board

I/O registers are aligned 32-bit big-endian words. Byte and halfword accesses to the board fault. Read-only registers reject writes; writes to supervisor-only registers from user mode cause a privilege violation.

| Address | Register | Access / meaning |
| --- | --- | --- |
| `$0200` | `KEY_STATE` | Read-only held-key bitmask: bit 0 left, 1 right, 2 fire, 3 start, 4 pause. |
| `$0204` | `CYCLE_COUNT` | Read-only low 32 bits of executed instruction count. |
| `$0208` | `FRAME_COUNT` | Read-only virtual VBL count. |
| `$0210` | `IRQ_PENDING` | Read-only pending bits: bit 0 VBL, bit 1 keyboard state changed. |
| `$0214` | `IRQ_MASK` | Readable; supervisor-writable. Bit 0 enables VBL IRQ, bit 1 keyboard IRQ. Reset enables VBL only. |
| `$0218` | `IRQ_ACK` | Write-one-to-clear pending bits; supervisor-only. Reads as zero. |
| `$0220` | `VBL_STATUS` | Read-only; bit 0 is set while VBL is pending. |
| `$0224` | `BOARD_ID` | Read-only `$54444332` (`TDC2`). |

All other addresses in `$0200–$02FF` are unassigned and fault. Addresses `$0300–$03FF` are reserved for future board expansion and currently fault.

### Keyboard

The browser maps Left/Right arrows (or A/D), Space, Enter, and Escape to the `KEY_STATE` bits. The register reports keys currently held. A key-down or key-up transition sets the keyboard bit in `IRQ_PENDING`; holding a key does not repeatedly queue events. The browser clears held keys when the window loses focus. Keyboard IRQs can be masked; programs can poll `KEY_STATE` without enabling interrupts.

### Clock, VBL, and IRQ

One virtual video frame occurs every 16,667 executed instructions. At each VBL, `FRAME_COUNT` increments and the VBL bit is set in `IRQ_PENDING`. `VBL_STATUS` reflects that pending bit and is cleared when VBL is acknowledged through `IRQ_ACK`.

The CPU samples pending interrupts between instructions when CUSR.I is set and a pending source is enabled by `IRQ_MASK`. Enabled sources share CPU vector 8; the handler identifies sources by reading `IRQ_PENDING`. The built-in ROM IRQ handler preserves R1, acknowledges pending sources, restores the interrupted state with RTI, and returns to the interrupted program. Programs may poll the cycle counter and frame count without using interrupts.

## Reset, ROM, and loading

Reset initializes RAM, ROM, system registers, video memory, keyboard state, the frame counter, and the interrupt controller. Vector 0 points to the ROM reset stub at `$8000`; vectors 1–7 and reserved vectors point to the default fatal handler at `$8100`; vector 8 points to the IRQ handler at `$8104`.

The reset stub begins in supervisor mode with interrupts disabled. The loader supplies the program entry in `BOOT_ENTRY`, places the initial interrupt-enable value in R11, and the entry address in R12. The stub executes `LD CUSR,R11`, then branches through R12; the program starts in user mode with interrupts enabled. The default user and supervisor stack tops are `$8000` and `$4000`. Programs should treat R1–R12 as unspecified on entry.

The minimal ROM fatal-exception handler halts with `SWI 63`; an exception cause is shown by the UI. The default IRQ handler acknowledges pending sources and returns. This is a bring-up ROM, not a general BIOS: there is no disk, serial console, sound device, or general-purpose ROM service API. The browser supplies the assembled program directly; there is no persistent storage or filesystem.

Ordinary data loads and stores cannot access ROM. ROM is executable and inspectable in the UI memory viewer, but debugger inspection does not grant the emulated CPU data-read access.

## Video and browser UI

The framebuffer begins at `$00010000` and contains 38,400 bytes. Pixels are packed MSB first, one bit per pixel; set bits render white and clear bits render black. The browser redraws the bitmap when framebuffer memory changes.

Use the UI's memory viewer to inspect system-page registers, RAM, ROM, and video memory. Load `examples/io-board-test.asm` to test keyboard and frame polling; it records the current key bitmask and frame count at `$00004000` and `$00004004`. `examples/rotating-cube.asm` demonstrates keyboard-driven rotation, and `examples/bouncing-ball.asm` demonstrates a VBL-paced animated sprite that erases its prior position.

For a quick test, load an assembly source and choose **Reset / Assemble**. This initializes the machine and boots the program from ROM. Choose **Max speed** for practical VBL timing; the slower UI run intervals intentionally throttle execution.
