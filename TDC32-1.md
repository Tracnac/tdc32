# TDC32.01 CPU Specification

## Overview

TDC32.01 is a 32-bit, big-endian, load/store processor with 32-bit instructions and a flat 32-bit address space. Instruction fetch advances PC by 4 bytes. Aligned 32-bit data accesses are required. SP grows downward by 4 bytes per stack word. Ordinary instructions take one cycle; memory and divide operations may take additional cycles. Floating-point values use IEEE-754 binary32.

The architectural register file has 16 entries, R0–R15. R0 reads as zero and discards writes, while instructions and their flag effects still execute. Code is relocatable. ROM is protected and is not exposed through ordinary data loads or stores. Any instruction encoding or operand form not explicitly defined here is illegal.

## Notation and immediate values

- Decimal integers use ordinary signed notation, e.g. `-12` or `23`.
- `0x` introduces hexadecimal, `0b` binary, and `0o` octal literals; underscores may separate digits, e.g. `0x1234`, `0b0000_0001`, and `0o17`.
- Instruction operands use decimal, `0x`, `0b`, or `0o` notation. Numeric directive operands also accept `$` for hexadecimal and `%` for binary (for example, `.adr $2000`).
- Labels are case-insensitive. Branch and PC-relative label operands are assembled as offsets from the address of the current instruction.
- An encoded signed immediate is sign-extended unless an instruction explicitly specifies zero extension; see **Immediate extension** for instruction-specific rules.

## Registers

| Register | Name / purpose |
| --- | --- |
| R0 | Constant zero; writes are discarded. |
| R1–R8 | General-purpose 32-bit registers. |
| R9–R12 | General-purpose registers; also F9–F12 floating-point aliases. |
| R13 | CUSR, the control/status register. |
| R14 | SP, stack pointer. |
| R15 | PC, program counter. |

PC may be read as a source or address base. A PC read yields the address of the current instruction, not the incremented fetch address. Branches, `RTS`, `RTI`, and system entry may change PC. SP may be read by `LD Rd, SP`; it may be written by `LD SP, Rs`, which traps if the new value is not 4-byte aligned, or by the defined stack operations.

### CUSR and flags

CUSR[31:16] and reserved bits read as zero. CUSR[15:8] is the control unit (CU) register; CUSR[7:0] is SR. The defined bits are:

| Bit | Name | Meaning |
| --- | --- | --- |
| 15 | T | Trap state / CPU halted after a fatal entry failure. |
| 14 | S | Supervisor mode. |
| 13:8 | - | Reserved; reads as zero. |
| 7:6 | - | Reserved; reads as zero. |
| 5 | I | Interrupt enable; `I=1` enables interrupts. |
| 4 | - | Reserved; reads as zero. |
| 3 | V | Signed overflow / floating-point exception status as specified per instruction. |
| 2 | C | Carry / no-borrow status as specified per instruction. |
| 1 | N | Negative result. |
| 0 | Z | Zero result. |

Writes to CUSR[15:8] are ignored unless the CPU is in supervisor mode. Reserved bits are always zero. SR[7:0] is user-readable and writable, subject to reserved bits being zero. System entry and return rules below define updates to S, I, and T.

## Instruction encoding

All instructions are one 32-bit word.

### Common format

| Bits | Meaning |
| --- | --- |
| 31 | Mode |
| 30:24 | Opcode (7 bits) |
| 23:20 | Rd |
| 19:16 | Rs |
| 15:0 | Immediate (16 bits) |

Mode 1 is valid only for `LD` and `ST`. Any other opcode in mode 1 traps as an invalid instruction. Mode 0 uses the common format except for Bxx branches. For `RTS` and `RTI`, `Rd`, `Rs`, and the immediate must be zero.

### Bxx branch format

When mode is 0 and the opcode is `B`, decode the word as:

| Bits | Meaning |
| --- | --- |
| 31 | Mode (0) |
| 30:24 | Opcode (7 bits) |
| 23:20 | Condition |
| 19:16 | Target base register (Rd) |
| 15:0 | Address displacement |

For a label branch, `Rd=PC`; the signed 16-bit displacement is word-scaled. Its range is -32768 to 32767 words (-131072 to +131068 bytes from the instruction PC). The assembler rejects unaligned or out-of-range targets. For a register-target branch, `Rd` is the target register and the displacement is zero. A linked branch pushes `PC+4` before branching.

Symbolic code and data references are PC-relative. A memory operand with `R0` as its base uses an absolute address.

## Addressing and instruction forms

### Register forms

`R0` reads as zero. For `ADD`, `result = old Rd + Rs + sext(immediate)`. For example, `ADD R1, R0, imm` adds the immediate to the old value of R1.

In mode 0, `LD Rd, imm` loads a zero-extended immediate (`Rs=R0`). `LD Rd, Rs` copies Rs (immediate zero). `LD Rd, label` uses PC and a PC-relative displacement. `Rs` may be PC or SP. `LD SP, Rs` requires a 4-byte-aligned value. No other instruction may write SP directly.

Memory operations use mode 1 and the same effective-address rule: `EA = Rs + sext(offset)`. The base register is always encoded in `Rs`; for `ST`, the value to store is in `Rd`.

- `LD Rd, (Rs)` and `LD Rd, 0(Rs)` load from `Rs`.
- `LD Rd, offset(Rs)` loads from `Rs + sext(offset)`.
- `ST (Rd), Rs` stores Rs at the address in Rd; the assembler places the address base in the encoded `Rs` field and the stored value in `Rd`.
- `ST offset(Rd), Rs` stores Rs at the address `Rd + sext(offset)`.

`R0` is zero, so `$1000(R0)` accesses fixed address `$1000`. Label operands use PC-relative offsets unless `R0` is the memory base; `label(R0)` uses the absolute label address.

For stack-frame access, use ordinary displacements such as `LD R1, 4(SP)` and `ST 4(SP), R1`. Stack accesses follow the same address rule.

### Immediate extension

- Arithmetic immediates for `ADD`, `SUB`, `ADC`, `SBC`, `MUL`, and `DIV` are sign-extended from 16 bits. `MULU` immediates are zero-extended.
- Shift and rotate immediates use the low 5 bits as the shift count.
- `CMP` immediates and branch displacements are sign-extended.
- `AND`, `OR`, and `XOR` immediates are zero-extended.
- `LD` immediates are zero-extended.
- Unsigned division immediates are zero-extended; signed division immediates are sign-extended.

| Operation | Flags |
| --- | --- |
| ADD, SUB, ADC, SBC, CMP, NEG | Set NZCV |
| MUL, MULU, DIV, DIVU, MULH, MULHU, DIVQ, DIVQU | Set NZV; C unchanged |
| AND, OR, XOR, NOT, BTST, BSET, BCLR, BCHG | Set NZ; clear C and V |
| SHL, SHR, ROL, ROR, ASR | Set NZC; clear V, except C is unchanged for count zero |
| FADD, FSUB | Set NZV; clear C |

| FTOI | Set NZV; C unchanged |
| FABS, FNEG | Set NZ; clear V; C unchanged |

### B

Bxx uses the branch format above. The condition codes are listed below. For `B<COND> label`, `Rd=PC`; encode `(label - PC) / 4` as a signed 16-bit value. Execution computes `target = PC + (sext(address16) << 2)`. The assembler rejects unaligned or out-of-range targets. `B<COND> imm` uses the same signed word-scaled displacement.

`B<COND> Rx` uses `Rd=Rx` and address zero; it branches to the absolute address in Rx. The target must be 4-byte aligned. `BA` uses condition `1111` and is always taken. `BSR` uses condition `1110`, pushes `PC+4`, and branches to its target. `BSR` accepts a label or register target.

### SWI

`SWI imm` enters the system service selected by its immediate. Its entry behavior and immediate ranges are defined under **System entry, vectors, and return**.

## Stack operations and SP

SP is R14 and grows downward. Stack accesses must remain in installed RAM, and SP must be word-aligned. `PUSH Rs` encodes Rs in the `Rs` field; `Rd` and the immediate are zero. It decrements SP by 4 and stores Rs at `[SP]`. `POP Rd` encodes Rd in the `Rd` field; `Rs` and the immediate are zero. It loads `[SP]` into Rd and increments SP by 4. Both use mode 0 and do not change flags.

`RTS` loads PC from `[SP]` and increments SP by 4. `RTI` is legal only in supervisor mode; it restores CUSR and PC from the supervisor stack.

Stack-frame accesses use ordinary offsets, such as `LD R1,4(SP)` and `ST 4(SP),R1`. `LD SP, Rs` writes an aligned SP. For stack-frame allocation, use `LD R1,SP`, `SUB R1,16`, then `LD SP,R1`; the new SP must be aligned and within the valid stack range.

A linked branch pushes `PC+4` on the stack before branching.

## Integer operations

All integer results are 32-bit. `Rd` is the destination and, where specified, its old value is also an input. `Rs` and the immediate provide the other operand values. `R0` reads as zero. `LD` and `ST` use the addressing rules above and do not change flags. `NEG` and `NOT` encode their destination in Rd and source in Rs, with immediate zero. Bit instructions encode the input and result register in Rd, set Rs to zero, and place the bit index in immediate[4:0]; immediate[15:5] must be zero. `BTST` does not write Rd.

- `CMP`: compares Rd with either Rs or the sign-extended immediate, sets NZCV, and does not change either operand.
- `ADD`: `result = old Rd + Rs + sext(immediate)`; sets NZCV. Thus `ADD R1, R0, n` adds zero and `n` to the old value of R1.
- `SUB`: subtracts the encoded register and immediate operands from old Rd; sets NZCV. C=1 means no borrow; C=0 means borrow.
- `ADC`: adds the encoded register and immediate operands and incoming C to old Rd; sets NZCV.
- `SBC`: subtracts the encoded register and immediate operands and `(1-C_in)` from old Rd; sets NZCV.
- `MUL`: low 32 bits of the product; sets NZV, preserves C.
- `MULU`: low 32 bits of the unsigned product; sets NZV, preserves C.
- `NEG`: `Rd = -Rs`; sets NZCV as a subtraction from zero.
- `NOT`: `Rd = bitwise NOT Rs`; sets N and Z, clears C and V.
- `BTST`: tests bit `immediate[4:0]` of Rd without changing Rd; sets N and Z from the masked test result, clears C and V.
- `BSET`, `BCLR`, `BCHG`: set, clear, or toggle bit `immediate[4:0]` of Rd, respectively. They set N and Z from the result and clear C and V.
- `MULH`: high 32 bits of the signed 64-bit product; sets NZV, preserves C. `MULHU` computes the unsigned product.
- `DIV`: signed quotient; sets NZV, preserves C. Signed division truncates toward zero. `INT_MIN / -1` returns `INT_MIN` and sets V; it does not trap. Division by zero traps.
- `DIVU`: unsigned quotient; sets NZV, preserves C. Division by zero traps.
- `DIVQ`: signed quotient to Rd and remainder to Rs; sets NZV, preserves C. Signed remainder has the sign of the dividend. `Rd == Rs` is illegal. Division by zero traps. `DIVQU` computes the unsigned quotient and remainder.
- `AND`, `OR`, `XOR`: bitwise operation; set N and Z, clear C and V.
- `SHL`, `SHR`, `ROL`, `ROR`, `ASR`: count is the low 5 bits. Set N and Z, set C to the last bit shifted/rotated out, and clear V. If the count is zero, the result is unchanged, N and Z are updated, and C is unchanged. SHR is logical; ASR replicates the sign bit.

## Floating-point operations

F9–F12 alias the binary32 values held in R9–R12. Floating-point arithmetic and conversion instructions use register forms unless otherwise specified.

- `FADD`, `FSUB`: binary32 add/subtract; set NZV and clear C.
- `FMUL`, `FDIV`: binary32 multiply/divide; set NZV, clear C. Invalid operations raise the FP-invalid trap; divide-by-zero behavior follows IEEE-754 unless it is an invalid operation.
- `FABS Rd, Rs`: copy the absolute value of Rs to Rd; sets N and Z, clears V, leaves C unchanged.
- `FNEG Rd, Rs`: with immediate zero, negate the binary32 value in Rs and write it to Rd; sets N and Z, clears V, leaves C unchanged.
- `FTOI Rd, Fs`: truncate finite, in-range binary32 toward zero; sets NZV, preserves C. NaN, infinity, or out-of-range conversion raises the FP-invalid trap.
- `ITOF Fd, Rs`: convert signed 32-bit integer to binary32; does not modify flags.
- `FCMP Fd, Fs`: floating-point comparison; sets NZCV. It has no immediate form. Invalid comparison (including NaN) raises the FP-invalid trap.

## System entry, vectors, and return

### Entry sequence

SWI, IRQ, and synchronous traps use one system-entry mechanism. On entry:

1. Push the saved PC, then push the current CUSR. Since the stack grows down, CUSR is at the top of the resulting frame.
2. Set S=1 and I=0.
3. Transfer control to the ROM entry for the vector.

For a synchronous trap, the saved PC is the faulting instruction address. For SWI and IRQ, it is the address of the next instruction. If entry itself faults (for example, because the stack is invalid), set T=1 and halt; do not attempt another entry.

### Vectors

Hardware vector numbers and causes:

| Vector | Cause |
| --- | --- |
| 0 | Reset |
| 1 | Stack fault |
| 2 | Divide by zero |
| 3 | Illegal instruction, including privilege violation |
| 4 | PC overflow |
| 5 | Illegal memory access |
| 6 | Alignment / bus fault |
| 7 | Floating-point invalid |
| 8 | IRQ |

The hardware vector table occupies ROM addresses `0x8000–0x80FF`; vector n is the big-endian 32-bit entry at `0x8000 + 4*n`. SWI immediates `0x0001–0x7FFF` select ROM services as defined by `rom.md`; service entry and return use the system-entry rules above. Ordinary data loads/stores cannot access ROM. SWI `-1` halts the CPU. SWI `0` requests reset through vector 0 and enters the reset state (it does not require a normal interrupt stack frame).

### Reset

Reset enters ROM vector 0 with S=1, I=0, and all other defined flags clear. The boot ROM initializes SP. R1–R12 are undefined after reset. R0 remains zero. T is clear on reset.

## Traps and memory protection

- Stack fault: a push/pop leaves installed RAM or SP is unaligned.
- Division by zero.
- Illegal instruction or privilege violation.
- PC overflow.
- Illegal memory access: ordinary data access outside installed RAM or to any ROM address.
- Bus/alignment fault: unaligned word access.
- Floating-point invalid: invalid comparison or invalid/out-of-range conversion as specified above.

Data memory is big-endian. A word access must be 4-byte aligned. ROM is protected and inaccessible through ordinary LD/ST. An instruction's data address must be within installed RAM; otherwise it traps. Stack faults use vector 1; alignment faults use vector 6; remaining trap causes use the vector table above.

## ASM (Cheatsheet)

### Assembler directives (not instructions)

| Directive | Meaning |
| --- | --- |
| `.adr address` | Set the assembly location counter. Subsequent code or data is assembled at this address. |
| `.align n` | Advance the location counter to the next address divisible by the positive byte alignment `n`. |
| `.code label` | Define `label` at the current location as a code symbol. The location must be word-aligned and in installed RAM. |
| `.data name` | Define a data label at the current location. It does not itself reserve storage. |
| `.str "text"` | Emit the quoted string as US-ASCII bytes; no terminator is added. Non-ASCII characters are rejected. |
| `.u8 value[, ...]` | Emit one unsigned byte per value (0–255). |
| `.u16 value[, ...]` | Emit unsigned 16-bit values in big-endian byte order (0–65535). |
| `.u32 value[, ...]` | Emit unsigned 32-bit values in big-endian byte order (0–4294967295). |

Labels are declared as `:name` and are case-insensitive. Data directives emit values consecutively without automatic padding; labels name the address of the next emitted byte. `.align n` advances the location counter but emits no data; reset memory in the skipped range remains zero. Within data values, `$` alone denotes the current location counter; `($ - label)` evaluates the byte distance from the label to the current data address. For example, after `.data hello`, `.str "A"`, `.align 4`, and `.u32 0xFFFFFFFF`, `.u8 ($ - hello)` emits 8. `.str` emits exactly the string bytes and does not append a zero byte. Code and data declarations may use forward label references where an immediate or data value permits them. Directives are assembler conveniences and do not have opcodes. CPU word loads and stores remain subject to the 4-byte alignment rule.

### Symbolic LD operands (assembler syntax)

The assembler resolves label operands as follows:

- `LD Rd, label` computes the address of `label` using a signed 16-bit PC-relative displacement.
- `LD Rd, (label)` loads the word at `label` using PC-relative addressing. The label must be word-aligned, and the signed 16-bit displacement must fit.
- `LD Rd, label(Rs)` uses a PC-relative label displacement for any base except `R0`: `label - instruction-PC`, which must fit the signed 16-bit field. With `R0`, the label address is used as an absolute offset and must fit that field.
- `LD Rd, (Rs)` loads from the address in `Rs`.

### Pseudo-ops (not opcodes)

`INC Rd` aliases `ADD Rd, R0, 1`. `DEC Rd` aliases `SUB Rd, R0, 1`.

`LI Rd, imm32` is an assembler pseudo-op. It expands to one `LD` when the value fits an unsigned 16-bit literal. Otherwise it expands to `LD Rd, high16`, `SHL Rd, 16`, and `OR Rd, low16`. The assembler must reject a literal that is out of range for a single `LD` rather than silently truncating it. Thus `LI R1,-1` expands to produce `0xFFFFFFFF`.
