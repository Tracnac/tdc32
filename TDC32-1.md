# TDC32.01 CPU Specification

## Overview

TDC32.01 is a 32-bit, big-endian, load/store processor with 32-bit instructions and a flat 32-bit address space. Instruction fetch advances PC by 4 bytes. Aligned 32-bit data accesses are required. SP grows downward by 4 bytes per stack word. Ordinary instructions take one cycle; memory and divide operations may take additional cycles. Floating-point values use IEEE-754 binary32.

The architectural register file has 16 entries, R0–R15. R0 reads as zero and discards writes, while instructions and their flag effects still execute. Code is relocatable. ROM is protected and is not exposed through ordinary data loads or stores. Any instruction encoding or operand form not explicitly defined here is illegal.

## Notation and immediate values

- Decimal integers use ordinary signed notation, e.g. `-12` or `23`.
- `0x` introduces hexadecimal, `0b` binary, and `0o` octal literals; underscores may separate digits, e.g. `0x1234`, `0b0000_0001`, and `0o17`.
- Instruction operands use only decimal, `0x`, `0b`, or `0o` notation. For compatibility, numeric directive operands may also use `$` for hexadecimal and `%` for binary (for example, `.adr $2000`).
- Labels are case-insensitive. Branch and PC-relative label operands are assembled as offsets from the address of the current instruction.
- An encoded signed immediate is sign-extended unless an instruction explicitly specifies zero extension; see **Immediate extension** for instruction-specific rules.

## Registers

| Register | Name / purpose |
| --- | --- |
| R0 | Constant zero; writes are discarded. |
| R1–R8 | General-purpose 32-bit registers. |
| R9–R12 | General-purpose registers; also F9–F12 floating-point aliases. |
| R13 | CUSR, the control/status register. |
| R14 | SP, stack pointer. |
| R15 | PC, program counter. |

PC may be read as a source or address base. A PC read yields the address of the current instruction, not the incremented fetch address. Only a branch instruction may write PC. SP may be read by `LD Rd, SP`; it may be written only by register-mode `LD SP, Rs`, which traps if the new value is not 4-byte aligned, or by the defined stack operations.

### CUSR and flags

CUSR[31:16] and reserved bits read as zero. CUSR[15:8] is the control unit (CU) register; CUSR[7:0] is SR. The defined bits are:

| Bit | Name | Meaning |
| --- | --- | --- |
| 15 | T | Trap state / CPU halted after a fatal entry failure. |
| 14 | S | Supervisor mode. |
| 13:8 | - | Reserved; reads as zero. |
| 7:6 | - | Reserved; reads as zero. |
| 5 | I | Interrupt enable; `I=1` enables interrupts. |
| 4 | - | Reserved; reads as zero. |
| 3 | V | Signed overflow / floating-point exception status as specified per instruction. |
| 2 | C | Carry / no-borrow status as specified per instruction. |
| 1 | N | Negative result. |
| 0 | Z | Zero result. |

Writes to CUSR[15:8] are ignored unless the CPU is in supervisor mode. Reserved bits are always zero. SR[7:0] is user-readable and writable, subject to reserved bits being zero. System entry and return rules below define updates to S, I, and T.

## Instruction encoding

All instructions are one 32-bit word:

| Bits | Meaning |
| --- | --- |
| 31:27 | Opcode (5 bits) |
| 26 | M / instruction modifier |
| 25:24 | Addressing mode |
| 23:20 | Rd, or branch condition for B |
| 19:16 | Rs |
| 15:12 | Rt, or immediate[15:12] |
| 11:0 | Immediate[11:0], or reserved |

Addressing modes:

- `00` - immediate / PC-relative branch displacement.
- `01` - register.
- `10` - indirect / indexed memory access or defined stack form.
- `11` - three-register operation; bits[11:0] must be zero unless explicitly stated.

Unless stated otherwise, M must be zero. Reserved fields must be zero. An invalid mode, modifier, or reserved field is an illegal instruction.

M=0 selects the base form, while M=1 selects the instruction-specific variant below.
| Instruction and mode | M=0 | M=1 |
| --- | --- | --- |
| B, modes `00`/`01` | Branch | Linked branch; push PC+4 before branching |
| B, mode `10` | RTS/RTI special forms only, M=0 | Illegal |
| LD, mode `00` | Zero-extended immediate load | `LD.L`; combine prior upper half of Rd with the immediate |
| LD, mode `10`, SP base | SP-relative load | Pop (`LD Rd,(SP)+`); immediate must be zero |
| ST, mode `10`, SP base | SP-relative store | Push (`ST -(SP),Rs`); immediate must be zero |
| MULH, DIV, DIVQ, supported modes | Signed operation | Unsigned operation |

For every other opcode/mode combination, M=1 is illegal. Mnemonic suffixes and aliases such as `.L`, `JSR`, `DIVU`, and `MULHU` are assembler syntax; M is the encoded field.

## Addressing and instruction forms

### Immediate and register forms

The following two-operand operations use `Rd` as both the first input and destination unless otherwise specified:

- `LD Rd, imm` / `LD Rd, Rs`
- `SWI imm` in mode `00`, with M=0.
- `ADD`, `SUB`, `ADC`, `SBC`, `MUL`, `DIV`, `AND`, `OR`, `XOR`, `ROL`, `ROR`, `SHL`, `SHR`, `ASR` with `Rd, imm`, `Rd, Rs`, or `Rd, Rs, imm`
- `BPR Rd, imm` / `BPR Rd, Rs`
- `FABS Rd, Rs`, `FADD`, `FSUB`, `FMUL`, `FDIV`, `FTOI`, and `ITOF` in their defined register forms

`LD Rd, imm` loads a zero-extended 16-bit literal. `LD Rd, Rs` copies the selected register value; `Rs` may be PC or SP. `LD SP, Rs` is allowed only in register mode and requires a 4-byte-aligned value. No other instruction may write SP directly.

### Indexed memory forms

For loads, the effective address is `Rs + sext(imm16)`. For stores, it is `Rd + sext(imm16)`. The sum is a 32-bit address; data accesses must be word-aligned and within installed RAM.

- `LD Rd, (Rs)` - load from `Rs + 0`.
- `LD Rd, imm(Rs)` - load from `Rs + sext(imm16)`.
- `ST (Rd), Rs` - store `Rs` at `Rd + 0`.
- `ST imm(Rd), Rs` - store `Rs` at `Rd + sext(imm16)`.

PC is a valid base register and is read as the current instruction address.

Immediate-mode ALU instructions also have a three-operand form, `OP Rd, Rs, imm`: the result is computed from Rs and the sign- or zero-extended immediate as appropriate, then written to Rd. This form uses mode `00`; Rs is encoded in its register field. It is distinct from mode `11`, which takes three registers.

### Three-register forms (mode `11`)

Mode `11` encodes `Rd, Rs, Rt`; bits[11:0] are zero. It is defined for `ADD`, `SUB`, `ADC`, `SBC`, `MUL`, `DIV`, `AND`, `OR`, `XOR`, `ROL`, `ROR`, `SHL`, `SHR`, `ASR`, `FADD`, `FSUB`, `FMUL`, `FDIV`, `MULH`, and `DIVQ`.

For ordinary arithmetic and logical operations, the result is written to `Rd` from inputs `Rs` and `Rt`. `ADC` and `SBC` additionally use the incoming C flag as specified below. `DIVQ` writes quotient to `Rd` and remainder to `Rs`; `Rd` and `Rs` must differ.

### Immediate extension

- Arithmetic immediates for `ADD`, `SUB`, `ADC`, `SBC`, `MUL`, and `DIV` are sign-extended from 16 bits.
- Shift and rotate immediates use the low 5 bits as the shift count.
- `BPR` immediates and branch displacements are sign-extended.
- `AND`, `OR`, and `XOR` immediates are zero-extended.
- `LD` immediates are zero-extended.
- When M selects unsigned operation for `DIV`/`DIVQ`, an immediate divisor is zero-extended; signed forms sign-extend it.

`LD.L Rd, imm16` is `LD` with M=1 in immediate mode and combines the current upper half of Rd with the immediate: `Rd = (Rd << 16) | imm16`. For example, `LD R1,0x1234` produces `0x00001234`; followed by `LD.L R1,0x5678`, R1 is `0x12345678`.


## Branches and comparisons

### B

B uses `Rd` as the condition field. The condition codes are listed below. `B<COND> label` encodes the signed word displacement `(label - PC) / 4`; execution computes `target = PC + (sext(imm16) << 2)`. The assembler must ensure the target displacement is word-aligned and fits signed 16 bits. `B<COND> imm` uses the same signed word-scaled displacement. M=1 forms (mnemonic suffix `.L`) push `PC+4` and branch when the condition passes.

`B<COND> Rx` (mode `01`) branches to the absolute address in Rx. The target must be 4-byte aligned. Relocatable code can form a target with `ADD Rx, PC, label` and then branch through Rx. Only B writes PC.

`BA` is condition `1111`, always taken. `BA.L` is the linked always branch. `JSR` is an assembler alias for `BA.L` and accepts the same target forms (`JSR label` or `JSR Rx`); it pushes `PC+4` before branching. `B` with condition `1110` is RTI, not a branch; see **System entry, vectors, and return**. Other condition encodings are illegal unless listed.

### BPR and FBPR

`BPR Rd, imm` compares the integer value in Rd against a sign-extended immediate by performing `Rd - imm` for flags only. `BPR Rd, Rs` compares registers. Both set NZCV and do not change either operand. `FBPR` is register-only and compares binary32 floating-point values, setting comparison flags. An invalid floating-point comparison (including NaN where comparison is undefined) raises the FP-invalid trap.

### Condition codes

| --- | --- | --- |
| `0000` | EQ | Z = 1 |
| `0001` | NE | Z = 0 |
| `0010` | CS/HS | C = 1 |
| `0011` | CC/LO | C = 0 |
| `0100` | MI | N = 1 |
| `0101` | PL | N = 0 |
| `0110` | VS | V = 1 |
| `0111` | VC | V = 0 |
| `1000` | HI | C = 1 and Z = 0 |
| `1001` | LS | C = 0 or Z = 1 |

| `1101` | LE | Z = 1 or N != V |
| `1110` | RTI | Return from interrupt/trap; legal only in supervisor mode |
| `1111` | A / AL | Always |

## Stack operations and SP

SP is R14. It grows downward. A push decrements SP by 4 and stores one word; a pop loads one word and increments SP by 4. Every stack access must remain in installed RAM, and SP must be word-aligned.

| Assembly form | Encoding / effect |
| --- | --- |
| `LD Rd, imm(SP)` | Mode `10`, base Rs=SP, M=0; ordinary SP-relative load. |
| `LD Rd, (SP)+` | Mode `10`, base Rs=SP, M=1, immediate=0; pop to Rd. |
| `ST imm(SP), Rs` | Mode `10`, base Rd=SP, M=0; ordinary SP-relative store. |
| `ST -(SP), Rs` | Mode `10`, base Rd=SP, M=1, immediate=0; push Rs. |
| `LD Rd, SP` | Mode `01`; read SP. |
| `LD SP, Rs` | Mode `01`; write aligned SP. |
| `BA (SP)+` / `RTS` | B opcode, condition A, mode `10`, Rd=A, Rs=SP; pop PC. `RTS` is an assembler alias for `BA (SP)+`. |
| `RTI` | B opcode, condition RTI, mode `10`, Rs=SP; restore CUSR then PC. |

M=1 in mode `10` with any non-SP base is illegal. Immediate push is not defined; load the value into a register and use `ST -(SP), Rs`. For stack-frame allocation, use `LD R1,SP`, `SUB R1,16`, then `LD SP,R1` (or equivalent); the new SP must be aligned and within the valid stack range.

For a linked branch, push `PC+4` on the stack before branching. `BA (SP)+` returns by popping that address into PC. The RTS encoding uses Rs=SP (`1110`), not PC (`1111`).

## Integer operation semantics

All integer results are 32-bit. For two-operand forms, Rd is the left operand and destination. Three-operand forms use Rs and Rt as inputs and Rd as destination.

- `ADD`: `result = lhs + rhs`; sets NZCV.
- `SUB`: `result = lhs - rhs`; sets NZCV. C=1 means no borrow; C=0 means borrow.
- `ADC`: `result = lhs + rhs + C_in`; sets NZCV.
- `SBC`: `result = lhs - rhs - (1-C_in)`; sets NZCV.
- `MUL`: low 32 bits of the product; sets NZV, preserves C.
- `MULH`: high 32 bits of the 64-bit product; sets NZV, preserves C. M=0 selects signed 32-bit operands; M=1 selects unsigned operands. `MULHU` is assembler syntax for `MULH` with M=1.
- `DIV`: quotient; sets NZV, preserves C. M=0 is signed; M=1 is unsigned. `DIVU` is assembler syntax for M=1. Signed division truncates toward zero. `INT_MIN / -1` returns `INT_MIN` and sets V; it does not trap. Division by zero traps.
- `DIVQ`: quotient to Rd and remainder to Rs; sets NZV, preserves C. M=0 is signed; M=1 is unsigned. `DIVQU` is assembler syntax for M=1. Signed remainder has the sign of the dividend. `Rd == Rs` is illegal. Division by zero traps.
- `AND`, `OR`, `XOR`: bitwise operation; set N and Z, clear C and V.
- `SHL`, `SHR`, `ROL`, `ROR`, `ASR`: count is the low 5 bits. Set N and Z, set C to the last bit shifted/rotated out, and clear V. If the count is zero, the result is unchanged, N and Z are updated, and C is unchanged. SHR is logical; ASR replicates the sign bit.

For MULH and DIV forms, M selects signed or unsigned interpretation as listed above. The signedness aliases do not change the opcode.

## Floating-point operations

F9–F12 alias the binary32 values held in R9–R12. Floating-point arithmetic and conversion instructions use register forms unless otherwise specified.

- `FADD`, `FSUB`: binary32 add/subtract; set NZCV, Clear C.
- `FMUL`, `FDIV`: binary32 multiply/divide; set NZV, clear C. Invalid operations raise the FP-invalid trap; divide-by-zero behavior follows IEEE-754 unless it is an invalid operation.
- `FABS Rd, Rs`: copy the absolute value of Rs to Rd; sets N and Z, clears V, leaves C unchanged.
- `FTOI Rd, Fs`: truncate finite, in-range binary32 toward zero; sets NZV, preserves C. NaN, infinity, or out-of-range conversion raises the FP-invalid trap.
- `ITOF Fd, Rs`: convert signed 32-bit integer to binary32; does not modify flags.
- `FBPR Fd, Fs`: floating-point comparison; sets NZCV. It has no immediate form. Invalid comparison (including NaN) raises the FP-invalid trap.

## Flag behavior summary

| Operation | Flags |
| --- | --- |
| ADD, SUB, ADC, SBC, BPR | Set NZCV |
| MUL, DIV, MULH, DIVQ | Set NZV; C unchanged |
| AND, OR, XOR | Set NZ; clear C and V |
| SHL, SHR, ROL, ROR, ASR | Set NZC; clear V, except C is unchanged for count zero |
| FADD, FSUB, FBPR | Set NZCV |
| FMUL, FDIV, FTOI | Set NZV; C unchanged |
| FABS | Set NZ; clear V; C unchanged |
| ITOF | No flags modified |
| LD, ST, B, SWI | No user flags modified, except system entry/return rules |

## System entry, vectors, and return

### Entry sequence

SWI, IRQ, and synchronous traps use one system-entry mechanism. On entry:

1. Push the saved PC, then push the current CUSR. Since the stack grows down, CUSR is at the top of the resulting frame.
2. Set S=1 and I=0.
3. Transfer control to the ROM entry for the vector.

For a synchronous trap, the saved PC is the faulting instruction address. For SWI and IRQ, it is the address of the next instruction. If entry itself faults (for example, because the stack is invalid), set T=1 and halt; do not attempt another entry.

### Vectors

Hardware vector numbers and causes:

| Vector | Cause |
| --- | --- |
| 0 | Reset |
| 1 | Stack fault |
| 2 | Divide by zero |
| 3 | Illegal instruction, including privilege violation |
| 4 | PC overflow |
| 5 | Illegal memory access |
| 6 | Alignment / bus fault |
| 7 | Floating-point invalid |
| 8 | IRQ |

The hardware vector table occupies ROM addresses `0x8000–0x80FF`; vector n is the big-endian 32-bit entry at `0x8000 + 4*n`. SWI immediates `0x0001–0x7FFF` select ROM services as defined by `rom.md`; service entry and return use the system-entry rules above. Ordinary data loads/stores cannot access ROM. SWI `-1` halts the CPU. SWI `0` requests reset through vector 0 and enters the reset state (it does not require a normal interrupt stack frame).

### RTI

`RTI` is encoded as B condition `1110`, mode `10`, with SP as the base; M=0 and reserved/immediate fields zero. It is legal only in supervisor mode. RTI pops the saved CUSR and PC from the supervisor stack, then restores CUSR and transfers to the saved PC. An RTI attempted outside supervisor mode is an illegal instruction.

### Reset

Reset enters ROM vector 0 with S=1, I=0, and all other defined flags clear. The boot ROM initializes SP. R1–R12 are undefined after reset. R0 remains zero. T is clear on reset.

## Traps and memory protection

- Stack fault: a push/pop leaves installed RAM or SP is unaligned.
- Division by zero.
- Illegal instruction or privilege violation.
- PC overflow.
- Illegal memory access: ordinary data access outside installed RAM or to any ROM address.
- Bus/alignment fault: unaligned word access.
- Floating-point invalid: invalid comparison or invalid/out-of-range conversion as specified above.

Data memory is big-endian. A word access must be 4-byte aligned. ROM is protected and inaccessible through ordinary LD/ST. An instruction's data address must be within installed RAM; otherwise it traps. Stack faults use vector 1; alignment faults use vector 6; remaining trap causes use the vector table above.

## ASM (Cheatsheet)

### Assembler directives (not instructions)

| Directive | Meaning |
| --- | --- |
| `.adr address` | Set the assembly location counter. Subsequent code or data is assembled at this address. |
| `.align n` | Advance the location counter to the next address divisible by the positive byte alignment `n`. |
| `.code label` | Define `label` at the current location as a code symbol. The location must be word-aligned and in installed RAM. |
| `.data name` | Define a data label at the current location. It does not itself reserve storage. |
| `.str "text"` | Emit the quoted string as US-ASCII bytes; no terminator is added. Non-ASCII characters are rejected. |
| `.u8 value[, ...]` | Emit one unsigned byte per value (0–255). |
| `.u16 value[, ...]` | Emit unsigned 16-bit values in big-endian byte order (0–65535). |
| `.u32 value[, ...]` | Emit unsigned 32-bit values in big-endian byte order (0–4294967295). |

Labels are declared as `:name` and are case-insensitive. Data directives emit values consecutively without automatic padding; labels name the address of the next emitted byte. `.align n` advances the location counter but emits no data; reset memory in the skipped range remains zero. Within data values, `$` alone denotes the current location counter; `($ - label)` evaluates the byte distance from the label to the current data address. For example, after `.data hello`, `.str "A"`, `.align 4`, and `.u32 0xFFFFFFFF`, `.u8 ($ - hello)` emits 8. `.str` emits exactly the string bytes and does not append a zero byte. Code and data declarations may use forward label references where an immediate or data value permits them. Directives are assembler conveniences and do not have opcodes. CPU word loads and stores remain subject to the 4-byte alignment rule.

### Symbolic LD operands (assembler syntax)

These are assembler conventions over existing CPU encodings; they do not add opcodes:

- `LD Rd, label` computes the address of `label`, equivalent to `LEA Rd, label` / `ADD Rd, PC, label`. The assembler uses the signed PC-relative displacement `label - instruction-PC`; it must fit in 16 bits.
- `LD Rd, (label)` loads the word stored at `label` using PC-relative addressing. The label must be word-aligned; the assembler rejects an unaligned label. Its PC-relative displacement must fit in signed 16 bits.
- `LD Rd, label(Rs)` uses the label address as the immediate displacement and computes `Rs + sext(label)`. Since the displacement is signed 16-bit, non-PC label addresses are limited to `0x0000–0x7FFF`; larger symbols are rejected with an explanatory range error. For `label(PC)`, the assembler uses `label - instruction-PC` instead. The displacement is immediate, not a register; use `ADD` to form a register-indexed address, followed by `LD Rd, (base)`.
- `LD Rd, (Rs)` remains an indirect load from the address in `Rs`.

### Pseudo-ops (not opcodes)

`NEG Rd, Rs` aliases `SUB Rd, R0, Rs`. `NOT Rd, Rs` expands to `LI R12, 0xFFFFFFFF` followed by `XOR Rd, Rs, R12`; R12 and its F12 alias are clobbered. Since R12 holds the temporary mask, NOT operands must be R0–R11. `INC Rd` aliases `ADD Rd, Rd, 1`. `DEC Rd` aliases `SUB Rd, Rd, 1`.

`MIN Rd, Rs` and `MAX Rd, Rs` are signed comparisons. They expand to `BPR`, a conditional branch, and (when required) `LD`; the comparison flags are preserved. `ABS Rd, Rs` computes signed absolute value using `BPR` and conditional `SUB`/`LD`. For nonnegative inputs it leaves C=1,V=0; for negative inputs its final `SUB` flags apply, including V=1 for INT_MIN. If Rd=R0, R12 is used to compute flags and is clobbered.

`BTST Rd, n`, `BSET Rd, n`, `BCLR Rd, n`, and `BCHG Rd, n` accept a bit index `n` from 0 to 31. They are assembler macros using R12 as a scratch register, so R12 (and its F12 alias) is clobbered. Rd must be R0–R11 because it cannot also hold the temporary mask. The macros load a one-bit mask (or its complement for BCLR) into R12, then use AND/OR/AND/XOR respectively. BTST writes the AND result to R0, leaving Rd unchanged while updating flags. All four use the final logical instruction's flags: NZ are set from its result, C and V are cleared. The expansions appear as individual LD/LD.L and logical instructions in the execution trace.

`LI Rd, imm32` is an assembler pseudo-op, not an opcode. It expands to one `LD` when the value fits an unsigned 16-bit literal; otherwise it expands to `LD Rd, high16` followed by `LD.L Rd, low16`. The assembler must reject a literal that is out of range for a single `LD` rather than silently truncating it. Thus `LI R1,-1` expands to produce `0xFFFFFFFF`.

`LEA Rd, label` is an assembler alias for the single instruction `ADD Rd, PC, label`. It computes the relocatable address of the label and is equivalent to `LD Rd, label`; `LD Rd, (label)` loads the contents stored there. Execution traces display the translated `ADD` instruction.
