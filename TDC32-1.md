# TDC32.01 CPU Specification

## Overview

TDC32.01 is a 32-bit, big-endian, load/store processor with 32-bit instructions and a flat 32-bit address space. Instruction fetch advances PC by 4 bytes. Aligned 32-bit data accesses are required. SP grows downward by 4 bytes per stack word. Ordinary instructions take one cycle; memory and divide operations may take additional cycles. Floating-point values use IEEE-754 binary32.

The architectural register file has 16 entries, R0–R15. R0 reads as zero and discards writes, while instructions and their flag effects still execute. Memory maps, reset wiring, boot firmware, and peripheral devices are defined by a virtual-machine platform; see [VM32-1.md](VM32-1.md). Assembler source conventions are documented in [TOOLS32-1.md](TOOLS32-1.md). Any instruction encoding or operand form not explicitly defined here is illegal.

## Notation and immediate values

- Unprefixed integers are decimal, e.g. `-12` or `23`.
- `$` prefixes a hexadecimal integer; `%` prefixes a binary integer.
- Operand examples in this specification use these prefixes, e.g. `LD R1, $1234` and `LD R2, %0001_0000`. Source-file and directive syntax is specified in [TOOLS32-1.md](TOOLS32-1.md).
- An encoded signed immediate is sign-extended unless an instruction explicitly specifies zero extension; see **Immediate extension** for instruction-specific rules.

## Registers

| Register | Name / purpose |
| --- | --- |
| R0 | Constant zero; writes are discarded. |
| R1–R8 | General-purpose 32-bit registers. |
| R9–R12 | General-purpose registers; also F9–F12 floating-point aliases. |
| R13 | CUSR, the control/status register. |
| R14 | SP, the active user or supervisor stack pointer (banked by CUSR.S). |
| R15 | PC, program counter. |

PC may be read as a source or address base. A PC read yields the address of the current instruction, not the incremented fetch address. Only `B`, `RTS`, `RTI`, supervisor-mode `POP PC`, and system entry may change PC. SP may be read by `LD Rd, SP`; it may be written by `LD SP, Rs` or by the defined stack operations. No other instruction may write SP. An unaligned or out-of-range value written to SP causes a stack fault (vector 1). The visible R14 selects the user stack when S=0 and the supervisor stack when S=1; changing S saves the old R14 bank and loads the new one. Valid stack ranges are implementation-defined.

### CUSR and flags

CUSR[31:16] and reserved bits read as zero. CUSR[15:8] is the control unit (CU) register; CUSR[7:0] is SR. R13 may be read as a register source. `LD R13, Rs` and `POP R13` write CUSR; RTI and system entry also update it. Data-processing instructions may not use R13 as Rd, so `ADD R13, ...` is illegal. The defined bits are:

| Bit | Name | Meaning |
| --- | --- | --- |
| 15 | T | Trap state / CPU halted after a fatal entry failure. |
| 14 | S | Supervisor mode. |
| 13 | I | Interrupt enable; `I=1` enables interrupts. |
| 12:8 | - | Reserved; reads as zero. |
| 7:4 | - | Reserved; reads as zero. |
| 3 | V | Integer arithmetic overflow (signed or unsigned) or finite-result binary32 overflow, as defined by the instruction. |
| 2 | C | Carry / no-borrow status as specified per instruction. |
| 1 | N | Negative result. |
| 0 | Z | Zero result. |

Writes to CUSR[15:8], including CU:I, are ignored unless the CPU is in supervisor mode. Reserved bits are always zero. SR[7:0] is user-readable and writable, subject to reserved bits being zero. A supervisor write that changes S also switches the active R14 bank. System entry and return rules below define updates to S, I, and T.

## Instruction encoding

All instructions are one 32-bit word.

### Common format

| Bits | Meaning |
| --- | --- |
| 31 | Mode |
| 30:24 | Opcode (7 bits) |
| 23:20 | Rd |
| 19:16 | Rs |
| 15:0 | Immediate (16 bits) |

Mode 1 is valid only for `LD`, `ST`, `LDB`, `LDH`, `LDSB`, `LDSH`, `STB`, and `STH`. Any other opcode in mode 1 traps as an invalid instruction. Mode 0 uses the common format except for Bxx branches. Unless an instruction form assigns a meaning to a field, that field must be zero; nonzero unused fields make the instruction invalid.

### Bxx branch format

When mode is 0 and the opcode is `B`, decode the word as:

| Bits | Meaning |
| --- | --- |
| 31 | Mode (0) |
| 30:24 | Opcode (7 bits) |
| 23:20 | Condition |
| 19:16 | Target base register (Rs) |
| 15:0 | Address displacement |

For a PC-relative target, `Rs=PC`; the signed 16-bit displacement is word-scaled. Its range is -32768 to 32767 words (-131072 to +131068 bytes from the instruction PC), and the target must be word-aligned. For a register-target branch, `Rs` is the target register and the displacement is zero.

Symbolic code and data references are PC-relative. A memory operand with `R0` as its base uses an absolute address.

Floating-point arithmetic uses two-register forms: Fd is both the destination and first operand; Fs is the second operand.

In mode 0, `LD` uses `Rs` to select the source:

- If `Rs=R0`, the instruction loads the zero-extended immediate.
- If `Rs=PC`, the instruction loads the address `PC + sext(immediate)`, where the immediate is a signed byte displacement.
- For any other `Rs`, the immediate must be zero; the instruction copies Rs. A nonzero immediate with another base register is illegal in mode 0.

`LD` may not write PC; `LD PC, Rs` is illegal. `LD SP, Rs` is the only load form that may write SP and requires a 4-byte-aligned value. Stack instructions update SP as described below.

Memory operations use mode 1 and the same effective-address rule: `EA = Rs + sext(offset)`. The base register is always encoded in `Rs`. `ST` encodes the address base in `Rs` and the stored value register in `Rd`.

For example, if `table` is word-aligned, `LD R1, table(R2)` reads the word at `R2 + (table - PC)`. The `table - PC` difference and `R2` offset are in bytes. `R2` must be a multiple of 4 so the effective address is aligned.

- `LD Rd, (Rs)` and `LD Rd, 0(Rs)` load a 32-bit word from `Rs`.
- `LD Rd, offset(Rs)` loads a 32-bit word from `Rs + sext(offset)`.
- `LDB Rd, memory` loads one byte and zero-extends it to 32 bits. It has no alignment requirement.
- `LDSB Rd, memory` loads one byte and sign-extends it to 32 bits. It has no alignment requirement.
- `LDH Rd, memory` loads a big-endian 16-bit halfword and zero-extends it. The effective address must be 2-byte aligned.
- `LDSH Rd, memory` loads a big-endian 16-bit halfword and sign-extends it. The effective address must be 2-byte aligned.
- `ST (Rbase), Rvalue` stores the 32-bit `Rvalue` at the address in `Rbase`. The encoding places `Rbase` in `Rs` and `Rvalue` in `Rd`.
- `ST offset(Rbase), Rvalue` stores the 32-bit `Rvalue` at `Rbase + sext(offset)` and uses the same encoding-field mapping.
- `STB memory, Rvalue` stores the low 8 bits of `Rvalue` at the effective address; it has no alignment requirement.
- `STH memory, Rvalue` stores the low 16 bits of `Rvalue` as a big-endian halfword; the effective address must be 2-byte aligned.

`R0` is zero, so `$1000(R0)` accesses fixed address `$1000`. Label operands use PC-relative offsets unless `R0` is the memory base; `label(R0)` uses the absolute label address.

### Immediate extension

- Signed immediates for `ADD`, `SUB`, `ADC`, `SBC`, `MUL`, `MULH`, `DIV`, and `DIVQ` are sign-extended from 16 bits. Unsigned immediates for `MULU`, `MULHU`, `DIVU`, and `DIVQU` are zero-extended. `LDU` uses its unsigned 16-bit immediate directly as the upper half of the result; it is not extended.
- Shift and rotate immediates use the low 5 bits as the shift count. `GETB` and `PUTB` use `immediate[1:0]` as byte index n; `immediate[15:2]` must be zero.
- `CMP` immediates and branch displacements are sign-extended.
- `AND`, `OR`, and `XOR` immediates are zero-extended.
- Numeric `LD` immediates are zero-extended. `LD Rd, label` and `LD Rd, label(Rs)` with a base other than R0 use signed PC-relative byte displacements; with R0, the label address is an absolute byte offset.

### B

Bxx uses the branch format above. The condition codes are listed above. For a PC-relative target, encode its displacement from the current instruction as a signed 16-bit word offset. Execution computes `target = PC + (sext(address16) << 2)`. The target must be aligned and in range. An immediate displacement is in bytes, must be a multiple of 4, and is encoded as displacement/4.

`B<COND>` with a register target uses `Rs=Rx` and displacement zero; it branches to the absolute address in Rx. An unaligned register target causes an alignment fault (vector 6). `BA` uses condition `1111` and is always taken. `BSR` uses condition `1110`, pushes `PC+4`, and branches to its target. The all-zero instruction word is reserved.

### SWI

`SWI imm` enters the system service selected by its immediate. Its entry behavior and immediate ranges are defined under **System entry, vectors, and return**.

## Stack operations and SP

SP is R14 and grows downward. The CPU maintains separate user and supervisor SP banks selected by CUSR.S. Each active SP must be word-aligned, and stack accesses must remain within the corresponding stack range supplied by the implementation.

`PUSH Rs` encodes Rs in the `Rs` field; `Rd` and the immediate are zero. It reads Rs before decrementing SP. Then it decrements SP by 4 and stores the saved value at `[SP]`. Thus `PUSH SP` stores the pre-decrement value. The active user or supervisor stack bank is selected by CUSR.S.

`POP Rd` encodes Rd in the `Rd` field; `Rs` and the immediate are zero. It reads `[SP]` using the old SP, then increments SP by 4 and writes the loaded value to Rd. The pop must remain within the active stack bank. In supervisor mode, `POP SP` is allowed: the loaded value replaces the incremented SP and must be word-aligned and within the supervisor stack bank, or a stack fault occurs. In supervisor mode, `POP PC` is allowed: the loaded value becomes PC. It checks alignment before committing the pop; an unaligned target traps on POP before its own SP update. In user mode, `POP SP` and `POP PC` cause a privilege violation. `PUSH` and `POP` do not change flags.

`RTS` loads the return PC from `[SP]`. It checks alignment before committing the return. An unaligned target traps on the RTS instruction before its own SP update; exception entry then uses the supervisor stack. On success, RTS increments the active SP by 4 and transfers to the loaded PC. `RTI` is legal only in supervisor mode. It reads CUSR from `[SP]` first, then PC from `[SP+4]`. It checks PC alignment before committing the pop; an unaligned target traps on RTI before its own SP or CUSR update. On success, RTI advances the supervisor SP by 8, restores CUSR (and thus the selected SP bank), and transfers to the saved PC.

Stack-frame accesses use ordinary offsets, such as `LD R1,4(SP)` and `ST 4(SP),R1`. `LD SP, Rs` requires an aligned value in the active stack bank. Otherwise, it causes a stack fault (vector 1).

To allocate a stack frame, copy SP to R1, subtract the frame size, then copy R1 back to SP. For example: `LD R1,SP`, `SUB R1,16`, `LD SP,R1`. The new SP must be aligned and within the valid stack range.


## Integer operations

All integer results are 32-bit. `Rd` is the destination. Some instructions also use its old value as an input. `Rs` and the immediate provide other operands. `R0` reads as zero. `LD` and `ST` follow the addressing rules above and do not change flags.

`NEG` and `NOT` encode the destination in `Rd` and source in `Rs`. Their immediate is zero. Bit instructions use `Rd` as the input and, except for `BTST`, as the destination. They encode `Rs` as zero. The bit index is in immediate[4:0]; immediate[15:5] must be zero. `BTST` does not write `Rd`.

- `CMP`: compares Rd with the selected register or sign-extended immediate operand. It sets NZCV and does not change either operand.
- `ADD`: `result = old Rd + Rs + sext(immediate)`; sets NZCV.
- `SUB`: subtracts the encoded register and immediate operands from old Rd; sets NZCV. C=1 means no borrow; C=0 means borrow.
- `LDU Rd, imm16`: `Rd = (imm16 << 16) | (old Rd & $FFFF)`. The `Rs` field must be zero. The immediate must be in the range 0–65535. LDU does not modify flags. For example, `LD R1, $5678` followed by `LDU R1, $1234` leaves R1 as `$12345678`.
- `ADC`: adds the encoded register and immediate operands and incoming C to old Rd; sets NZCV.
- `SBC`: subtracts the encoded register and immediate operands and `(1-C_in)` from old Rd; sets NZCV.
- `MUL Rd, Rs` and `MUL Rd, imm` multiply old Rd by the selected operand. `MUL Rd, Rs, imm` multiplies Rs by the sign-extended immediate. All forms write the low 32 product bits to Rd. N and Z come from that low word. V=1 if the full signed product does not fit in 32 bits; otherwise V=0. C is unchanged.
- `MULU` uses the same forms with unsigned operands and a zero-extended immediate. It writes the low 32 product bits to Rd. N and Z come from that word. V=1 if the full product exceeds `$FFFFFFFF`; otherwise V=0. C is unchanged.
- `NEG`: `Rd = -Rs`; sets NZCV as a subtraction from zero.
- `SWPH Rd`: swap the high and low 16-bit halves of Rd in place. Rs and the immediate are zero. It does not modify flags. For example, `$12345678` becomes `$56781234`.
- `SWPB Rd`: reverse the byte order of Rd in place. Rs and the immediate are zero. It does not modify flags. For example, `$12345678` becomes `$78563412`.
- `GETB Rd, n`: replace Rd with the zero-extended byte `old Rd[8*n+7:8*n]`. `n` is 0–3; n=0 selects bits[7:0] and n=3 selects bits[31:24]. Flags are unchanged.
- `PUTB Rd, Rs, n`: replace byte n of old Rd with `old Rs[7:0]`. `n` is 0–3, with n=0 selecting bits[7:0] and n=3 selecting bits[31:24]. Flags are unchanged.
- `NOT`: `Rd = bitwise NOT Rs`; sets N and Z, clears C and V.
- `BTST`: tests bit `immediate[4:0]` of Rd without changing Rd. Z=1 when the selected bit is clear. N=1 only when bit 31 is selected and set. C and V are cleared.
- `BSET`, `BCLR`, `BCHG`: set, clear, or toggle bit `immediate[4:0]` of Rd, respectively. They set N and Z from the result and clear C and V.
- `MULH Rd, Rs` computes the high 32 bits of old Rd times Rs. `MULH Rd, Rs, imm` computes the high 32 bits of Rs times the sign-extended immediate. N and Z come from the high word. V=1 if the full signed product does not fit in 32 bits; otherwise V=0. C is unchanged.
- `MULHU` uses the same forms with unsigned operands and a zero-extended immediate. N and Z come from the high word. V=1 if the high word is nonzero; otherwise V=0. C is unchanged.
- `DIV Rd, Rs` and `DIV Rd, imm` divide old Rd by the selected divisor. `DIV Rd, Rs, imm` divides Rs by the sign-extended immediate. The quotient is written to Rd. Signed division truncates toward zero. `INT_MIN / -1` returns `INT_MIN` and sets V=1; other successful divisions set V=0. N and Z come from the quotient. C is unchanged. Division by zero traps.
- `DIVU` uses the same forms with unsigned operands and a zero-extended immediate. It writes the quotient to Rd. N and Z come from the quotient; V=0 and C is unchanged. Division by zero traps.
- `DIVQ Rd, Rs` divides old Rd by Rs. `DIVQ Rd, Rs, imm` divides old Rd by the sign-extended immediate; Rs receives the remainder in this form. Both forms write the quotient to Rd and remainder to Rs. N and Z come from the quotient, not the remainder. Signed remainder has the sign of the dividend; for `INT_MIN / -1`, the remainder is zero. `Rd == Rs` is illegal. `INT_MIN / -1` sets V=1; other successful divisions set V=0. C is unchanged. Division by zero traps.
- `DIVQU` uses the same operand and result arrangement as `DIVQ`, with unsigned division and a zero-extended immediate. N and Z come from the quotient; V=0 and C is unchanged. Division by zero traps.
- `AND`, `OR`, `XOR`: bitwise operation; set N and Z, clear C and V.
- `SHL`, `SHR`, `ROL`, `ROR`, `ASR`: operate on old Rd. In the `Rd, Rs` form, the count is `Rs[4:0]`; in the `Rd, imm` form, it is `immediate[4:0]`. Set N and Z, set C to the last bit shifted/rotated out, and clear V. If the count is zero, the result is unchanged, N and Z are updated, and C is unchanged. SHR is logical; ASR replicates the sign bit.

## Floating-point operations

F9–F12 alias the binary32 values held in R9–R12. Floating-point register operands must use F9–F12; R1–R8 are not valid floating-point operands. Floating-point arithmetic and conversion instructions use register forms unless otherwise specified.

Arithmetic and `ITOF` use IEEE-754 round-to-nearest, ties-to-even. Subnormal values are supported with gradual underflow; results are not flushed to zero. Underflow and inexact rounding do not trap or set V.

For `FADD`, `FSUB`, `FMUL`, and `FDIV`, invalid cases are signaling-NaN operands, opposite-signed infinities added, equal infinities subtracted, zero multiplied by infinity, zero divided by zero, and infinity divided by infinity. Quiet NaNs propagate through arithmetic without trapping. `FCMP` traps on any NaN. `FTOI` traps on NaN, infinity, or an out-of-range value. Invalid operations trap before committing the instruction result or flags. Divide-by-zero with a nonzero numerator follows IEEE-754 and does not set V.

- `FADD`, `FSUB`: binary32 add/subtract. Fd is both the destination and first operand; Fs is the second operand. N and Z reflect the result. C is cleared. V is set only if finite operands overflow the binary32 range; otherwise V=0.
- `FMUL`, `FDIV`: binary32 multiply/divide with the same operand roles. N and Z reflect the result. C is cleared. V is set only if finite operands overflow the binary32 range; otherwise V=0.
- `FABS Fd, Fs`: clear the sign bit of Fs and write the result to Fd; sets N and Z, clears V, leaves C unchanged. NaN inputs do not trap.
- `FNEG Fd, Fs`: toggle the sign bit of Fs and write the result to Fd; sets N and Z, clears V, leaves C unchanged. NaN inputs do not trap.
- `FTOI Rd, Fs`: truncate finite, in-range binary32 toward zero; sets N and Z from the integer result, clears V, and preserves C.
- `ITOF Fd, Rs`: convert signed 32-bit integer to binary32; does not modify flags.
- `FCMP Fd, Fs`: compare Fd with Fs. For ordered values, N=1 iff Fd<Fs, Z=1 iff Fd=Fs, C=1 iff Fd>=Fs, and V=0. An unordered comparison (either operand is NaN) raises the FP-invalid trap before updating NZCV.

## System entry, vectors, and return

### Entry sequence

Except for the special `SWI 0` and `SWI 63` cases, SWI, IRQ, and synchronous traps use one system-entry mechanism. A synchronous trapping instruction commits no register, memory, SP, or flag changes. The system-entry sequence itself changes SP, CUSR, and PC.

On entry:

1. Save the current CUSR, switch to the supervisor stack if necessary, and set S=1 and I=0.
2. Push the saved PC, then push the saved CUSR. Since the stack grows down, CUSR is at the top of the resulting frame.
3. Transfer control to the handler selected for the vector by the implementation.

RTI pops CUSR and PC from the supervisor stack. Restoring CUSR switches back to the saved user stack when returning to user mode.

For a synchronous trap, the saved PC is the faulting instruction address. For SWI and IRQ, it is the address of the next instruction. If entry itself faults (for example, because the stack is invalid), set T=1 and halt; do not attempt another entry.

### Vectors

Hardware vector numbers and causes:

| Vector | Cause |
| --- | --- |
| 0 | Reset |
| 1 | Stack fault |
| 2 | Divide by zero |
| 3 | Illegal instruction, including privilege violation |
| 4 | PC overflow |
| 5 | Illegal memory access |
| 6 | Alignment / bus fault |
| 7 | Floating-point invalid |
| 8 | IRQ |

Vector entries 9–63 are reserved. Vector table placement, access permissions, and reset contents are implementation-defined.

`SWI n` accepts an unsigned immediate from 0 to 63; values 64–65535 are illegal. SWI is allowed in user mode. `SWI 0` requests platform reset and `SWI 63` halts; both bypass normal system entry. `SWI 1–8` dispatch through the corresponding vector entry and use the system-entry rules above. `SWI 9–62` are reserved and trap as illegal instructions. Memory protection and execute-only regions are defined by the platform.

### Reset

On reset, the CPU enters supervisor mode with I=0 and begins at the reset address supplied by the implementation. Platform firmware initializes the stack banks and may establish a program entry environment. R0 remains zero and T is clear.

## Traps and memory protection

- Stack fault: a push/pop leaves its active stack bank or SP is unaligned; writing an unaligned or out-of-bank value to SP with `LD SP, Rs` also causes this fault.
- Division by zero.
- Illegal instruction or privilege violation.
- PC overflow: a sequential `PC+4`, PC-relative branch-target calculation, or linked-branch return address falls outside the 32-bit address range `0`–`$FFFFFFFF`. PC arithmetic does not wrap.
- Illegal memory access: instruction fetch or data access to an address that the implementation does not map or permit for that access type.
- Bus/alignment fault: unaligned halfword or word access, or unaligned register-branch target.
- Floating-point invalid: invalid comparison or invalid/out-of-range conversion as specified above.

Instruction fetch requires a 4-byte-aligned PC. Alignment is checked first, so an unaligned PC at fetch causes an alignment fault (vector 6). `RTS`, `RTI`, and `POP PC` check return-target alignment before committing their SP/CUSR changes. The implementation defines which memory regions are executable; fetch outside them causes an illegal memory access (vector 5).

Data memory is big-endian. `LD` and `ST` access aligned 32-bit words. `LDB`, `LDSB`, and `STB` access bytes; `LDH`, `LDSH`, and `STH` access 2-byte-aligned halfwords. `GETB` and `PUTB` manipulate register bytes only; they do not access memory. Ordinary data loads and stores check alignment before range and protection. A misaligned halfword or word access causes an alignment fault (vector 6). Address mapping, memory protection, and device-access widths are implementation-defined.

`PUSH`, `POP`, `RTS`, and `RTI` validate the active stack pointer and implementation-defined bank bounds. An unaligned pointer or one that leaves its bank causes a stack fault (vector 1). Remaining trap causes use the vector mechanism above.

## Glossary

- **CU:** Control unit register, stored in CUSR[15:8]. It contains control bits such as supervisor mode and interrupt enable.
- **Load/store:** A processor design where ordinary memory transfers use explicit load (`LD`) and store (`ST`) instructions; arithmetic operates on registers.
- **Big-endian:** A byte order where the most significant byte of a multi-byte value is stored at the lowest address.
- **Sign-extended:** A signed value is widened by copying its sign bit into the new upper bits, preserving its numeric value.
- **NZCV:** The Negative, Zero, Carry, and Overflow status flags. Their meanings and update rules depend on the instruction.
- **System entry:** The process used for an interrupt, software interrupt, or synchronous trap. The CPU saves state on the stack, changes control bits, and transfers to the corresponding vector.
- **Word:** One 32-bit value, or 4 bytes.
- **Trap:** A synchronous exception that transfers control to a handler through a vector.
- **Vector:** A table entry that identifies the handler address for a reset, interrupt, or exception.
- **Supervisor/user mode:** Supervisor mode (`S=1`) allows privileged operations; user mode (`S=0`) restricts them.
- **PC-relative:** An address or displacement calculated relative to the current instruction's PC. Units depend on the instruction.
- **Unordered:** A floating-point comparison involving NaN, for which less-than, equal, and greater-than are not defined. `FCMP` traps on unordered values.
