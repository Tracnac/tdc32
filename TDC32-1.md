# CPU TDC32.01


32-bit processor, 32-bit instruction, all instructions are 1 cycle, big-endian, load/store architecture, Von Neumann flat memory model (32-bit wide), 32-bit accesses must be aligned on 32-bit boundaries, SP grows downward by decrementing 4 bytes, and PC fetch increment by step of 4 bytes, Intel-style syntax.

This CPU is a pure Frankenstein, it's a blend of many cpu architectures and tweaks from the 80's, 90's and even from RISC/V, enjoy the 15 instructions (see equivalency for more, but seriously nobody need more),
32 registers (all for free no restriction except R0 (Zero based)) and the 4Go flat memory access, ROM is accessible only via SWI instruction.

They're no hidden behaviors, if you make mistake, you will pay for it. Tweak it, kill it but beware no odd memory access ;)

## REGISTERS:

R0 ALWAYS ZERO, R0 as destination is void, but the instruction is executed (no dead path, set/preserve FLAGS)
R1..R28 general purpose registers
R29 Status register (alias SR)
[31:0] CUSR ([31:16] NOT USED + CU Register [15:8] + Status Register [7:0])
        [31:16]  NOT USED (SET TO 0).
        [15:15] T (TRAP CPU HALTED)
        [14:14] S (SUPERVISOR)
        [13:8] NOT USED (SET TO 0)
        [7:6] NOT USED (SET TO 0)
        [5:5] I Interrupt
        [4:4] X (Change the behavior for some instruction)
            MUL Rd, Rs (64-bit) => HI:LO → Rd = HI, Rs = LO
            DIV Rd, Rs => Rd = Quotient, Rs = Remainder (Warning that dividing by an immediate discard remainder)
            ADC/SBC carry/borrow operations
        [3:3] V (OVERFLOW)
        [2:2] C (CARRY)
        [1:1] N (NEGATIVE)
        [0:0] Z (ZERO)
R30 Stack pointer (alias: SP)
R31 Program counter (alias: PC)

## FLAG BEHAVIOR REFERENCE

ARITHMETIC:
ADD, SUB: Sets N, Z, C, V
MUL, DIV: Sets N, Z, V (C unaffected)

LOGICAL:
AND, OR, XOR: Sets N, Z; Clears C, V

SHIFTS/ROTATES:
SHL, SHR, ROL, ROR: Sets N, Z, C (last bit out); Clears V

COMPARISON:
BPR: Sets N, Z, C, V

MEMORY/CONTROL:
LD, ST: No flags modified
B (except BPR): No flags modified
SWI: User flags preserved; S, T may be set

## RULE:

ALL CODE IS RELOCATABLE.
ROM is protected and not exposed to memory.
[+-][0-9]+  decimal or signed offset
$           hexadecimal (unsigned)
%           binary (unsigned; underscores allowed, e.g. 0000_0001)
label = PC RELATIVE
Rs and Rd may be any general-purpose register.
SP (R30) has special syntax forms:  -(SP) and (SP)+
SP (R30) and PC (R31) are read-only, using SP or PC as destination will punish you, so no LD R30|R31, $0xXXXX
SR[7:0] are user accessible R/W, SR[15:8] is read-only.

## SPECIAL CASE
### OPCODE
#### B
B uses the standard 32-bit instruction format. The rd/cond field ([25:21]) holds the branch condition code.
B + condition forms the conditional branch (for example B + NE → BNE).
The 16-bit immediate is a signed offset, target = positive ? (label - PC) : (label - PC - 4)
Bit [25] is LINK AND BRANCH (PUSH/POP PC)

  B<COND> LABEL   => OP:00000 MODE:00 RD:0<COND> RS:00000 IMMEDIATE:LABEL
  B<COND>.L LABEL => OP:00000 MODE:00 RD:1<COND> RS:00000 IMMEDIATE:LABEL

=== BPR
BPR Updates SR flags (NZCV).

  BPR Rd, <immediate> => OP:00000 MODE:00 RD:RD RS:00000 IMMEDIATE:<immediate>
  BPR Rd, Rs => OP:00000 MODE:01 RD:RD RS:RS IMMEDIATE:<not used>

==== SP (R30) REGISTER:

SP (R30) is only accessible with LD and BA opcode.
Assembler must ensure that SP is not accessible directly, the syntax to access it must be -(SP), (SP)+

When used by BA, it act as RTS.

    LD, BA:

    LD -(SP), Rs or Immediate ; PUSH
    OP:00010 MODE:01 Rd:11110 Rs:Rs IMMEDIATE:<not used>
    OP:00010 MODE:01 Rd:11110 Rs:00000 IMMEDIATE:<immediate>

    LD Rd, SP
    OP:00010 MODE:0 Rd:Rd Rs:11110 IMMEDIATE:<not used>

    LD Rd, (SP)+ ; POP
    OP:00010 MODE:1 Rd:Rd Rs:11110 IMMEDIATE:<not used>

    BA (SP)+ ; POP to PC (RTS)
    OP:00000 MODE:1 COND:11111 REG:11110 IMMEDIATE:<not used>
